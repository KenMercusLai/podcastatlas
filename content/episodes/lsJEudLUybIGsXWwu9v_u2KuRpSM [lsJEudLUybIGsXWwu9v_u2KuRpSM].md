# 从三次转型到 Agent 工具市场：AI 应用创业如何建立差异化价值

## 概览

本期对谈围绕一个核心问题展开：当基础模型和通用 Agent 越来越强，AI 应用公司还能依靠什么建立独立价值？Trigg 创始人 Jason 与创始工程师石天鑫复盘了团队不到一年内从 Super Design、自动增长 Agent 到数据与工具市场的多次转型。

团队的关键判断是，短期内“零人公司”并不现实。客服、修复 Bug、监控等确定性工作可以自动化，但增长、创新和渠道判断仍然依赖人的品味与决策。因此，机会更可能存在于“人和 Agent 协作”，而不是彻底排除人的全自动系统。

Trigg 选择不再自建完整 Agent，而是嵌入 Claude Code、Codex 等通用 Agent 生态，为其提供实时数据、专业 API 和工具调用能力。团队希望通过统一入口、按量付费、跨平台使用和 Agent 反馈数据，成为面向 Agent 的中立工具市场。

对谈还讨论了 Loop Engineering、多 Agent 并行、模型选择，以及程序员在 AI 时代的职业变化。嘉宾认为，与其固守单项技能，不如保持对前沿模型的高强度使用，通过跨领域能力、快速实验和及时转型寻找新位置。

## 分段落总结

[00:05] **嘉宾与 Trigg 的产品定位**

[事实] 本期嘉宾是 Trigg 创始人 Jason 和创始工程师石天鑫，两人在创业前分别拥有 AI 产品、设计及大型互联网公司的工程经验。

[事实] Trigg 被介绍为面向数据和工具的“OpenRouter”，用户通过一个 key，即可让 Claude Code、Codex 或自建 Agent 调用不同的数据与 API。

[事实] 节目的核心问题是：当模型能力持续增强时，AI 应用公司如何创造独立且差异化的价值。

[02:20] **九个月内的三次创业转型**

[事实] 团队先后尝试了设计 Agent Super Design、自动增长 Agent Coolit，以及面向 Agent 的数据和工具市场 Trigg。

[事实] Super Design 起初是一个周末项目，可在 IDE 中生成多版前端或视觉设计；开源后数月获得了六千多个 GitHub Star，且主要依靠自然传播。

[事实] 团队由此认识到，开源是 AI 产品非常有效的营销方式，但当时认为 IDE 插件的商业化和用户覆盖存在限制，因而转向网页版产品。

[04:54] **模型与通用 Agent 吞噬垂直应用**

[事实] 团队放弃原有设计 Agent，一方面是因为 Gemini 等模型推动了各家基础模型前端能力的提升，另一方面是 Claude Code、Codex 及其 Skill 生态已经能够完成越来越多设计任务。

[事实] 团队曾担心依赖 IDE 会限制用户规模，但随后大量用户涌入通用 Coding Agent，证明此前对产品入口的判断发生了偏差。

[推测] 这次转型反映出垂直 AI 产品若只提供模型能力的浅层封装，很容易随着基础模型升级而失去优势。

[06:40] **Coolit 与“零人增长团队”的尝试**

[事实] 团队受到一款可自动搭建公司和执行业务任务的产品启发，开始开发面向已有业务的自动增长 Agent Coolit。

[事实] Coolit 尝试覆盖 SEO、内容营销、广告投放和客户开发，并在产品尚未完全准备好时通过预售获得了一些付费用户。

[事实] 实际运行后，团队发现从零搭建网站和工具相对容易，但为真实业务持续交付增长结果非常困难。

[事实] 增长渠道处于动态竞争中，识别尚未热门但可能在未来出现流量的关键词，需要人类判断和品味，难以完全交给 Agent。

[12:32] **用 Super Design 验证 AI 自动运营**

[事实] 停止 Coolit 后，团队暂停产品开发，用约两个月时间尝试以 AI 运营已有的 Super Design 业务，以验证自动化公司的可行性。

[事实] 实验显示，客服、Bug 修复等工作可以高度自动化，但增长工作需要大量人工介入。

[事实] 团队据此判断，未来六到十二个月内“零人公司”不是现实场景，更值得解决的是人和 Agent 大规模协作的问题。

[事实] 他们同时得出第二个判断：新产品应围绕 Claude Code 和 Codex 的生态构建。

[14:38] **一个插件带来的增长拐点**

[事实] 团队尝试了多种增长实验，但真正改变 Super Design 增长曲线的是发布 Codex 插件，而且没有进行额外宣发。

[事实] 插件发布时市场仍处早期，团队把已有 CLI 和 Skill 接入市场，并曾利用按字母排序的规则将名称改为“01 Super Design”，获得了短期靠前展示。

[事实] 该渠道带来了大量用户，而且来自插件渠道的用户流失率更低。

[推测] 早期平台生态中看似微小的产品适配和分发机制，可能比复杂的营销方案更能改变创业公司的增长曲线。

[16:28] **从内部工具到 Trigg 市场**

[事实] 团队观察到 Claude Code 和 Codex 已拥有大量用户，但完成专业工作时仍缺少实时数据与外部工具。

[事实] Coolit 开发过程中形成的数据与 API 中转层被单独拆出，成为 Trigg 的基础。

[事实] Trigg 发布约三周后，收入已达到 Super Design 的数倍；其收费方式是完全按调用量计费，不收固定月费。

[事实] 使用需求主要集中在获客、SEO、AEO、社交媒体以及图片和视频生成等场景。

[19:11] **聚合数据供应商的商业逻辑**

[事实] 许多垂直数据供应商原本就采用 API 按量收费，却缺乏触达终端用户的渠道，因此愿意进入聚合市场。

[事实] 同一领域通常存在数十家供应商，各自在覆盖范围、准确度和价格上有所不同，并不存在适合所有需求的单一最佳选择。

[事实] Trigg 希望像 Costco 一样，以中立角色筛选供应商，让用户以较高性价比获得适合具体任务的数据。

[事实] 专业业务所需的数据往往具有实时性，或无法通过普通搜索和浏览器自动化获取，因此通用模型不能仅依靠自身知识完成这些任务。

[20:53] **跨 Agent 的中立工具层**

[事实] 嘉宾认为，不同 Agent 可能凭借独有数据吸引特定用户，而 Trigg 希望让不同 Agent Harness 都能调用相同的工具。

[事实] 用户从 Claude Code 切换到 Codex 时，可以保留此前积累的工具调用方式和数据，获得跨平台使用能力。

[推测] 如果通用 Agent 入口继续快速更替，一个独立于具体模型和 Harness 的工具层，可能降低用户的迁移成本。

[22:53] **面向 Agent 的数据飞轮**

[事实] Trigg 接入了大量 AIGC 模型，并把每种模型擅长和不擅长的任务整理成 Skill，供用户的 Agent 选择。

[事实] 团队认为产品的直接使用者正在从人变成 Agent，因此会随机请求用户的 Agent 对 API 结果进行匿名反馈。

[事实] 系统可以根据反馈自动修复简单 Bug，并把有价值的功能建议交给团队处理。

[事实] Trigg 还计划沉淀各 API 在有效性、准确度和性价比方面的评分，使后续 Agent 能按照任务目标选择工具。

[推测] 对无法训练基础模型的应用公司而言，真实调用反馈可能成为改善产品和建立壁垒的重要数据资产。

[25:42] **从全栈 Agent 转向生态插件**

[事实] 团队早期同时构建 Harness、推理层、沙箱和 Memory，但每一层都有专门公司持续优化，很难全部做到最好。

[事实] 现在的策略是集中做好一部分能力，再嵌入 Claude Code 和 Codex 生态。

[事实] 嘉宾观察到，过去设计、营销等工种使用不同软件，现在越来越多工作开始汇聚到通用 Agent 入口。

[事实] 对视频编辑等任务，中间状态仍然重要：它让 Agent 能修改时间轴和素材，而不必每次重新生成完整成片。

[28:38] **借助大平台红利创业**

[事实] 嘉宾认为，Claude Code 和 Codex 向大众用户扩散仍会持续数年，小型创业公司可以借助这一趋势获得增长。

[事实] 自建 Agent 不仅开发范围广，模型 Token 成本也很高；通用 Agent 的订阅计划则让用户以固定费用获得远高于订阅价的模型调用额度。

[事实] 搜索、网页抓取、授权连接和数据 API 等原本偏基础设施的服务，开始同时服务开发者与不会编程的终端用户。

[事实] Agent 能自行理解和调用 API，使这类服务不再必须通过传统软件界面触达用户。

[32:01] **多 Agent 时代的新交互机会**

[事实] 嘉宾列举了任务完成提醒、多 Agent 会话管理、跨 Claude Code 与 Codex 转移任务等新工具。

[事实] 部分重度用户已经同时运行数十个甚至上百个 Session，由此出现任务追踪、上下文迁移和统一调度的需求。

[推测] 当并行 Agent 数量超过人的注意力上限后，管理 Agent 的界面和协调机制可能形成新的产品类别。

[34:10] **通过实验建立创业确定性**

[事实] Jason 认为创业期间收获最大的一段经历，是暂停产品开发、把 Super Design 当作实验对象的两个月。

[事实] 这段实验让团队确认两件事：短期内零人公司不成立；Claude Code 和 Codex 的生态存在巨大机会。

[事实] 团队放下自建系统的包袱后，发现直接使用市场上最好的通用 Agent，体验明显优于自己的 Harness。

[事实] 嘉宾认为，转型最痛苦的原因是不确定问题究竟来自 Skill、Prompt，还是方向本身；实际实验可以帮助减少这种不确定性。

[36:20] **Loop Engineering 的适用边界**

[事实] 嘉宾把公司工作分为创新和运营，认为创新无法依靠自动 Loop 完成，但运营中存在大量适合自动化的任务。

[事实] 四人团队曾持续面对黑客利用邀请奖励或免费额度攻击系统的问题，因此使用 Loop 监控风险行为并修补小漏洞。

[事实] 团队建议从职责单一、范围很小的 Loop 开始，例如只监控数据库风险或整理代码，以降低出错概率。

[事实] 多个小 Loop 可以相互监控和补偿，逐渐组成更复杂、更健壮的运营系统。

[38:50] **从单一对话转向多 Agent 并行**

[事实] 随着模型自主完成任务的质量提高，团队成员会同时运行五到十个 Session。

[事实] 工作方式也从纯本地转向云端与本地结合，并通过可交换上下文的工具管理多个执行环境。

[事实] 石天鑫借鉴“船长与大副”的模式，让一个主要 Agent 负责向其他 Agent 分发和转达任务。

[推测] 人在这种工作流中的角色正在从亲自执行任务，转向设定目标、调度资源和审核结果。

[40:19] **模型与工具的实际选择**

[事实] Jason 曾长期重度使用 Claude Code，后来因新模型在视频复刻等任务中的表现转向 Codex；石天鑫则长期并用两者，并让不同模型执行同一任务后比较结果。

[事实] 团队还使用提供云端沙箱的工具运行工作流，因为独立沙箱便于并行测试前端修改和 Bug 修复。

[事实] 嘉宾认为 Kimi、MiniMax 等模型在前端或视频生成方面各有优势，部分高速模型则适合低延迟路由和大规模数据过滤。

[事实] 团队尚未把体验不错的部分模型切入生产环境，原因是大规模使用时仍更看重稳定性。

[45:13] **程序员的职业十字路口**

[事实] 石天鑫认为，自己过去十年积累的 React 和前端开发技能正在因 AI 进步而降低稀缺性，因此选择加入创业团队探索更有挑战的工作。

[事实] 他认为程序员已经很难在纯编码速度上超过 AI，但仍可通过跨领域能力寻找新的位置。

[事实] Jason 表示，自己虽然是设计师，却更喜欢从产品角度思考并编写部分前端代码，这类跨领域经历反而可能在 AI 时代被释放出来。

[推测] 对多数知识工作者而言，未来的竞争重点可能从单项执行技能转向问题选择、产品判断和跨学科协作。

[47:09] **频繁转型中的焦虑与韧性**

[事实] 团队在不到一年内多次转型，也曾因长期缺少增长、遭遇额度盗刷等事件产生强烈挫败感和放弃念头。

[事实] Jason 判断是否继续一个方向的方法，是看还能否想到真正改变当前处境的实验；如果没有，就应考虑转向。

[事实] 团队认同“快速失败”：确认方向不成立后尽快结束，再尝试新的机会。

[事实] 新方向带来的希望，以及持续学习和进化的感受，是团队继续创业的重要动力。

[49:25] **在 AGI 预期下继续创业**

[事实] 嘉宾认为模型进化是 AGI 到来的必要条件之一，但实现路径仍有很多可能。

[事实] 团队成员都是 AI 重度用户，通过持续体验前沿产品，建立对未来六到十二个月机会的判断。

[事实] 即便出现能力极强的通用模型，它仍需要工具和数据；如果外部服务能以更低成本提供结果，模型依然可能选择调用它。

[推测] Trigg 的长期假设不是模型能力会停滞，而是无论模型多强，高性价比的数据获取和专业工具仍可能具有独立价值。

## 播客点评/总结

本期最有价值的部分，是嘉宾没有停留在“模型会不会吞噬应用”的抽象争论，而是用三次真实转型说明哪些能力已经被通用 Agent 替代、哪些工作仍然需要人的判断，以及团队如何通过实验修正认知。

讨论也给出了较清晰的 AI 应用创业方法：不要轻易自建完整技术栈；优先利用成熟平台的能力和分发；把资源集中在实时数据、专业工具、工作流中间状态和用户反馈等不容易被基础模型直接覆盖的环节。

其局限是 Trigg 上线时间仍短，节目没有披露具体收入、留存、供应商结构和单位经济数据，因此中立工具市场与数据飞轮能否形成长期壁垒，尚无法从转录稿确认。[推测] 平台自建工具、头部供应商直接接入模型，以及 API 服务同质化，都可能成为后续挑战。

本期适合 AI 创业者、产品经理、工程师及正在思考职业转型的人收听。它既呈现了快速 Pivot 的现实压力，也提供了一种较为务实的乐观：模型越强，旧价值会消失，但围绕新入口、新协作方式和新成本结构，仍会不断出现可被验证的机会。
