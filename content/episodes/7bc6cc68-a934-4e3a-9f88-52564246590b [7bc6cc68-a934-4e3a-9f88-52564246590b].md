# 从 Coding Agent 到 Personal Agent：灵光 2.0 如何打造“能帮你管事”的个人助理

## 概览

本期采访蚂蚁灵光负责人蔡伟，回顾灵光从信息获取、闪应用逐步演进为 Personal Agent 的过程。团队认为，模型的长程任务能力和主动服务能力已经越过关键门槛，AI 产品的核心形态也将从“一问一答”转向持续理解上下文、跟踪事项并适时采取行动。

灵光 2.0 的核心主张是“帮用户管事”，而不只是回答问题或执行一次性任务。为此，团队把产品基础单位设计为持续管理的“事项”，并将智能、服务供给与安全可信视为个人助理成立的三个必要条件。

节目也讨论了灵光的研发弯路、基础设施、安全隐私、生态开放、推理成本和商业模式。团队曾尝试基于 OpenClaw 构建系统，后来为了移动端体验、扩展性与可控性而转向自研 Agent Runtime；在商业化上，则考虑生产力付费与交易连接价值两条路径。

蔡伟结合视觉搜索、Google Photos、Google Lens 和两次创业经历，提出 AI 2C 产品的关键是把握技术能力跨越用户体验阈值的时点，并匹配尚未满足的真实需求。她认为 Personal Agent 有机会成为国民级应用，但竞争窗口有限，长期壁垒将来自用户上下文、迁移成本和服务生态。

## 分段落总结

[01:12] **灵光从信息助手演进为个人助理**

[事实] 灵光 1.0 并非单纯定位为 Coding Agent，其长期理念是站在模型能力边缘探索新的 AI 2C 产品。

[事实] 第一阶段的核心是以代码生成结构化页面，提高用户获取信息的效率，而不是只输出 Markdown 文本。

[事实] 随着模型可以生成语音、图片和可交互内容，团队进一步推出面向移动端的“闪应用”，让普通用户也能制作和分享应用。

[事实] 用户将闪应用用于工具、生日礼物等场景，促使团队上线灵光圈，承载介于工具与内容之间的创作与分享。

[06:53] **Personal Agent 方向的两项关键启发**

[事实] Cloud Code 展现出的长程任务和工具调用能力，让团队意识到模型已经能够完成复杂、跨工具的实际任务。

[事实] 蔡伟曾让 Cloud Code 监控股票并把异常波动推送至微信；系统通过第三方工具完成了这一原本超出她预期的任务。

[事实] “小龙虾”类产品进一步让团队认识到，模型可以突破聊天框，持续跟进用户关心的事情，并在适当的时候主动提醒、请示或行动。

[推测] 两类产品分别验证了“复杂任务完成能力”和“持续主动服务形态”，共同构成灵光 2.0 的产品前提。

[11:44] **对话只是交互方式，而非产品本质**

[事实] 团队认为，对话框可以是输入方式，但不必成为所有 AI 产品的结构主轴。

[事实] Personal Agent 的核心是持续管理和跟进用户关心的事情，而非接收一次指令、完成一次任务。

[事实] 团队判断这一能力足以支撑独立产品形态，而不只是现有聊天机器人的附属功能，因此从4月起全面推进灵光 2.0。

[事实] 灵光没有另做新应用，因为 Personal Agent 与其提高生活、工作效率的既有主张一脉相承。

[14:36] **从概念验证到模型与产品协同**

[事实] 春节到4月期间，团队重点判断 Personal Agent 是否值得成为独立产品，以及当时的模型能力是否已经足够。

[事实] 团队认为“小龙虾”式产品安装、配置和使用门槛过高，不能直接面向国内大众用户，需要将相关能力普惠化。

[事实] 灵光主要使用蚂蚁百灵模型，并与模型团队在预训练、中期训练和后训练阶段协同优化。

[事实] 自有模型使团队可以端到端控制知识、工具调用、规划、性能和成本，目前没有接入第三方模型的计划。

[19:46] **六个月研发中的架构弯路**

[事实] Personal Agent 需要一套复杂的 Agent Runtime，负责按时间、事件及用户状态调度工具和任务，其技术架构不同于聊天机器人或一次性任务引擎。

[事实] 团队早期曾基于 OpenClaw 架构开发约一至两个月，希望复用其插件生态。

[事实] OpenClaw 更适合操纵桌面电脑，难以满足移动端原生个人助理对扩展性和可控性的要求，因此团队最终放弃该方案并自研基础设施。

[事实] 生产系统还必须同时处理成本、吞吐量、延迟、并发和稳定性，工作量远高于制作可运行的演示。

[22:45] **好助理的标准：合时、懂你、有边界**

[事实] 团队认为，好助理应在最合适的时候提供最合适的信息并办理最合适的事情。

[事实] 主动提醒的频率和内容很难把握：过多会打扰用户，过少又会错过用户真正需要的信息。

[事实] 助理还必须知道行动边界，例如涉及付款时，当前版本必须提示用户并取得最终授权。

[事实] 灵光接入了蚂蚁的可信、隐私和安全能力，帮助用户管理数据与权限，并限制模型对私人信息的使用范围。

[26:24] **个人助理成立的三项必要条件**

[事实] 蔡伟将优秀个人助理的要素概括为智能、供给和安全可信。

[事实] “供给”指产品能够连接哪些工具和服务，以及实际可以为用户完成哪些事情。

[事实] 三方面都需要达到足够水位，任何一项存在明显短板，产品都很难满足普通用户的日常需求。

[事实] 团队观察到越来越多公司通过 MCP 等形式开放接口，因此对国内服务生态的长期开放持乐观态度。

[32:31] **后台执行使推理成本更可控**

[事实] Personal Agent 的许多任务在后台执行，对即时延迟的容忍度高于前台问答。

[事实] 后台任务可以采用更小的模型、成本更低的算力和错峰调度，从而提高 GPU 利用率。

[事实] 团队表示，常驻式 Agent 的成本并不会简单地随查询次数线性增长，灵光能够做到低于节目中引用的每月4美元推理成本估算，但未透露具体数字。

[事实] 灵光采用资源池与虚拟隔离方案，团队强调真正重要的是满足安全、隐私和合规要求，而不是以“独立云主机”作为安全保证。

[37:43] **多入口、硬件与上下文价值**

[事实] Instinct 等产品让团队看到 Personal Agent 不必局限于独立应用，还可以通过短信、通信软件和智能硬件触达用户。

[事实] 灵光现阶段优先采用应用形态，因为已有用户基础，且这一方向与原有产品主张一致。

[事实] 选择硬件时，团队更看重其能够提供多少上下文；掌握用户的语言、身体状态或行为信息，才能形成区别于普通提醒工具的价值。

[事实] 已连接的服务中，账单、邮箱和钉钉等包含大量个人上下文的场景使用较多，钉钉位列服务连接需求前三。

[43:00] **Personal Agent 不会成为唯一入口**

[事实] 蔡伟不认同由一个个人助理统一前台、把所有应用降为后台服务的极端格局，认为这会损失产品与社会的多样性。

[事实] 有些用户追求效率，愿意交给 Agent 选择餐厅、酒店或商品；另一些用户享受亲自挑选的过程，两类需求会长期并存。

[事实] 灵光当前主要解决效率型需求，但团队判断这类需求足够广泛，Personal Agent 有机会成长为国民级应用。

[推测] 未来更可能形成多个入口和多种交互形态共存的生态，而非单一助理完全替代现有应用。

[46:38] **克制的主动服务与“事项”产品结构**

[事实] 蔡伟认为 Muse 的突出之处是克制，以及对消息时机、内容和细节的精细调优。

[事实] 灵光将智能拆分为模型能力、Agent Harness 和产品表达三部分。

[事实] 灵光的基本单位不是对话或一次任务，而是持续管理的“事项”，内部称为 thread，例如健康、理财或家庭关系。

[事实] 产品因此强调“帮你管事”，通过事项结构承载持续消费上下文、跟踪进展和主动服务的能力。

[51:18] **上线反馈与当前短板**

[事实] 2.0 上线一周后，用户留存超出团队预期，蔡伟称其大致处于 Muse 的水位，但节目没有披露具体比例。

[事实] 用户对单次回答偶有错误的容忍度较高，却会因承诺托管的事情无法完成而明显失望。

[事实] 有用户吐槽“灵光能连接很多东西，但打不通公司的部门墙”；团队解释，支付宝中的许多服务来自第三方，不能未经授权直接接入。

[事实] 当前提醒详情页仍较粗糙，虽然用户可以通过对话要求调整内容和风格，但很多人不知道这一能力或无法准确表达需求。

[57:24] **场景泛化与用户群变化**

[事实] 上线前团队最想验证的是 Personal Agent 能否跨领域、跨会话并覆盖不同人群，同时保持较高黏性。

[事实] 初步使用场景覆盖金融理财、健康、娱乐、办公和智能硬件，泛化性好于团队预期。

[事实] 灵光 1.0 用户主要集中在一二线城市的白领和高知人群；2.0 上线后，安卓和鸿蒙用户占比提升。

[事实] 2.0 在 iOS、安卓和鸿蒙平台的留存接近，而1.0的 iOS 留存曾比另外两个平台高出10个百分点以上。

[推测] 团队认为这可能说明 Personal Agent 比信息获取型产品更加普惠，但也保留了 iOS 版本体验不佳这一替代解释。

[62:54] **商业模式与 Agent 交易生态**

[事实] 团队考虑两类商业模式：一是按事项或订阅收取生产力服务费用，二是从连接商家、影响决策和促成交易中获得价值。

[事实] 蔡伟判断，在中国商业生态中，连接和决策链路的潜在体量可能更大；生产力付费则有助于识别和分层重度用户。

[事实] 在未来交易网络中，消费者 Agent 与商家 Agent 可能直接交互，但现有平台仍可能通过聚合供给、辅助决策和完成履约继续创造价值。

[事实] 灵光目前尚未向普通商家开放 MCP 接入平台，但团队正在考虑相关方案。

[70:16] **蔡伟的 AI 产品经历与技术阈值**

[事实] 蔡伟2011年开始创业做服装等品类的视觉搜索，后来将公司出售给 Pinterest；此后参与 Google Photos 和 Google Lens 等产品研发。

[事实] 她认为技术能力通常连续进步，但用户感知是不连续的：只有当能力跨过体验阈值，才会引发产品范式迁移。

[事实] 她的第二次创业曾尝试用 GAN 生成短视频，但技术只能完成约30%的工作，其余部分仍需人工补足，未达到端到端交付要求。

[事实] ChatGPT 的泛化能力和直接面向公众开放令她感到震撼，也促使她重新思考有影响力的 AI 应用机会。

[推测] 这些经历强化了她对“技术是否真正跨过可用阈值”的重视，也影响了灵光对生产级体验的要求。

[87:03] **AI 2C 产品的方法与竞争壁垒**

[事实] 蔡伟将 AI 2C 产品方法概括为：把握技术发展趋势，并匹配尚未满足的用户需求。

[事实] 2C 的难点在于用户通常无法准确描述自己的需求，需要产品团队主动洞察；但一旦产品创造真实价值，用户行为会直接给出反馈。

[事实] Personal Agent 的壁垒包括长期积累的用户上下文、助理关系的排他性、迁移成本，以及供给生态带来的网络效应。

[事实] 她判断未来主流个人 Agent 会少于10个，甚至可能少于5个。

[事实] 她认为特定产品形态的竞争窗口通常只有一至两年，领先者需要持续保持约三至六个月的优势。

[91:58] **核心指标不是对话数，而是托管事项数**

[事实] 节目提到，灵光已托管超过160万个事项，累计执行超过300万次。

[事实] 团队把托管事项数作为最核心指标，同时观察用户规模、黏性和留存。

[事实] 产品外壳较容易模仿，但要同时做好效果、性能、稳定性和安全，蔡伟估计至少需要约半年工作量。

[事实] 团队希望下一个里程碑是托管事项数再提高一个数量级，即超过千万。

[事实] 托管事项数比用户数更能反映“帮用户管事”的实际价值，也能避免被打卡、单次问答等表面活跃指标误导。

[95:26] **竞争路径：应用、手机系统与可穿戴设备**

[事实] 团队判断 Personal Agent 市场竞争将迅速升温，并认为其具有急剧爆发的潜力。

[事实] 手机级 Agent 试图通过操作系统或设备能力直接调用已有服务，是解决供给问题的一条技术路径，但可能遭遇安全和合作方封禁问题。

[事实] 可穿戴设备能够获取声音、动作和日常行为等更多上下文，理论上适合 Personal Agent，但也会引入硬件和隐私方面的新挑战。

[事实] 灵光会关注这些路线，但当前没有采用直接操控其他应用的方式。

[推测] Personal Agent 的竞争可能不只发生在应用之间，还将扩展到操作系统、硬件入口和服务生态控制权。

[102:24] **围绕核心价值设计产品与评测**

[事实] 蔡伟认为，产品功能、评测体系和安全设计都应当从核心价值主张向外推导。

[事实] 如果脱离产品内核单独讨论某项功能，支持和反对双方都能提出理由，决策容易退化为口才竞争。

[事实] 灵光在4月已形成“持续盯住用户关心事项”的方向，后来从“盯”扩展为承担更多执行责任的“管”。

[事实] “管事”与问答或办事的本质区别，被概括为责任转移：用户不再负责不断发指令和检查结果，而是把一部分责任托付给助理。

[149:19] **未来目标与意外的智能硬件场景**

[事实] 团队希望未来一年覆盖不同职业、城市和年龄的用户，在生活及办公场景中切实节省时间、提高效率和生活质量。

[事实] 蔡伟最常使用灵光处理理财相关事务。

[事实] 最令她惊喜的场景，是灵光在未经专门训练的情况下连接智能硬件，并通过一段指令成功让扫地机器人行动。

[推测] 这一案例体现了通用 Agent 能力的开放性：真正有价值的使用方式可能由用户和模型共同发现，而不完全来自产品团队的预先设计。

## 播客点评/总结

本期的价值在于，它没有把 Personal Agent 只当作热门概念，而是从架构、模型协同、主动服务、安全边界、供给生态和成本调度等方面拆解了生产级产品的真实难度。“智能、供给、安全可信”三要素，以及从“办事”到“管事”的责任转移，是最清晰的两组产品框架。

节目也提供了难得的研发复盘，包括放弃 OpenClaw 路线、将事项而非对话设为基本单位，以及使用托管事项数而非对话数衡量价值。这些内容适合 AI 产品经理、Agent 开发者、创业者及关注消费级 AI 竞争格局的从业者。

局限在于，多项产品成效只给出了相对描述，缺少留存率、成本和用户规模等可独立比较的数据；产品上线时间较短，关于跨人群泛化、国民级应用潜力和竞争壁垒的判断仍需要更长期的数据验证。

[推测] 总体而言，这期节目既是一份灵光 2.0 的产品复盘，也呈现了一种更广泛的判断：个人助理的关键不在于多一个聊天入口，而在于用户是否愿意持续交付上下文、权限与责任，而产品又能否以足够可靠和克制的方式承接这些托付。
