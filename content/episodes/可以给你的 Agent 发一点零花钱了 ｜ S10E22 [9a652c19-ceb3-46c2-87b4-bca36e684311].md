# 可以给你的 Agent 发一点零花钱了 ｜ S10E22

## 概览

本期围绕 agent payment，也就是智能体支付展开，讨论从年初还显得过早的话题，为什么到 7 月已经变成 Visa、Mastercard、Stripe、Google、OpenAI 等大公司共同推进的方向。

节目把智能体支付拆成两类：一类是 agent 帮人完成购物、预订等消费链路，最终消费人仍是用户；另一类是 agent 在执行任务时，为了调用 API、购买 token、下载资料或使用外部服务，在小额额度内自主支付。嘉宾认为前者目前更容易被看见，后者更像新兴的 agent economy 基础设施。

讨论的核心不只是“agent 能不能付钱”，而是授权、信任、责任归属、商户接入成本和用户体验能否一起跑通。Clink 与 Visa 的 demo 被用来解释：中间层可以保存用户意图和授权信息，校验商品与上下文，再通过一次性支付能力完成交易，从而让责任链路更清楚。

后半段延伸到稳定币、国内外生态差异、商家与内容创作者的变现问题，以及未来半年到一年值得观察的市场信号。整体结论是：技术层面已经有不少可跑通的方案，但真正爆发仍依赖 agent 在普通用户中的普及、商户 agent ready、以及支付体验是否足够顺滑。

## 分段落总结

[00:12] **开场：为什么现在聊智能体支付**

[事实] 主持人说明本期话题是 agent payment，年初就想讨论，但当时行业似乎还没有准备好。

[事实] 到 7 月，主持人观察到已有许多大公司入场，也有多种 protocol 建立，问题从“要不要给 agent 钱”变成“什么时候能让 agent 帮我们买东西”。

[事实] 本期嘉宾包括 Clink 创始人兼 CEO Patrick Wu，以及多次做客节目的高宁。

[01:30] **Clink 的定位与 Patrick 的支付背景**

[事实] Patrick 介绍 Clink 希望做 global payments working with agents，重点是在交易链路里出现 agent 这个新角色后，补上生态中的衔接和信息连接。

[事实] Patrick 提到自己从 2014 年开始做支付，经历包括 Amazon retail payments、AWS 2B 支付、国内三方支付，以及大型出海电商平台的一号位支付角色。

[推测] Clink 的自我定位不是直接做一个面向用户的购物 agent，而更像支付网络、agent 平台和商户之间的基础设施层。

[02:32] **为什么 agent payment 在今年变热**

[事实] 高宁回顾说，约一年前 Manus 等 general agent 出圈后，非开发者开始感受到 agent 能力，也让人思考软件订阅和支付模式是否会变化。

[事实] 到今年年初，一些 agent 框架开始让 skill 被调用、被使用，并出现交易的可能。

[事实] 高宁提到 Stripe 的会上，电商交易和 agent payment 是非常重要的主题，推动了行业应用者关注这一方向。

[03:50] **两类场景：替人消费与自主小额支付**

[事实] 主持人把场景分成两类：一类是 agent 帮消费者完成购物，最后用户确认付款；另一类是 agent 自己有钱包或授权额度，用于买 API、token、交电费等任务中间环节。

[事实] Patrick 认可大方向上可以这样分，并补充第一类最终消费人是人类，agent 负责执行、检索、抢购或筛选等更有效率的动作。

[事实] 第二类场景中，agent 为了交付 report 或结果，可能需要生图、查研报、下载资料或付费调用服务，因此适合在小额度内自主执行。

[推测] 这一区分解释了为什么 agent payment 不只是电商结账问题，也涉及未来软件、数据、API 和内容服务的按需调用。

[06:16] **当前更容易看到的是 agentic commerce**

[事实] 主持人认为现阶段更常见的是用户让 OpenAI 或 Claude 搜索、比较后帮忙下单。

[事实] Patrick 表示电商场景在全球体量很大，其中一部分被 agent 化后，交易规模就会很可观。

[事实] 与此相比，虚拟服务、token 或 API 的按需付费仍是新兴场景，生态还不稳定、不成熟。

[推测] 大规模市场很可能先从成熟电商链路中出现，再逐步扩展到更细碎的数字服务和 agent 自主消费。

[07:28] **agent 直接付款的三重阻碍**

[事实] Patrick 说，当前很多 agent 仍停留在商品推荐，最后一步仍需要人点击支付或补充信息来闭环。

[事实] 他认为一个问题是 agent 的智力、质量和用户信任还没有到可以完全托付的程度。

[事实] 另一个问题是 agent 不应被信任去保管用户卡信息，否则盗刷和责任问题可能由用户承担。

[事实] 第三个问题是商户端较保守，担心 agent 下单后客户关系归属、订单责任和投入 ROI。

[10:00] **Clink 与 Visa 的智能体支付 demo**

[事实] Patrick 介绍 Clink 与 Visa 在 6 月底的活动上 co-launch 了 Visa Intelligent Commerce 相关产品，并执行了 APEC Visa 的第一笔相关交易。

[事实] Visa 对 Clink 的定位是 agent enabler，而不是传统意义上的 agent。

[事实] demo 中，agent 会把用户沟通上下文、限额、商品类型等信息传给 Clink，Clink 记录为 instruction 和 mandate，即用户意图授权。

[事实] 当 agent 找到商品并准备购买时，Clink 会校验商品是否符合原始上下文和授权，再把授权转化为 Visa 提供的一次性 agent 相关支付能力。

[事实] 交易完成后，Clink 把订单信息返回给前端 agent，agent 再告知用户下单成功和预计时间。

[12:26] **责任归属与法币体系的信任优势**

[事实] 主持人指出，这类协议和中间层主要解决交易出问题后责任在消费者、agent 公司、Visa 还是商家的问题。

[事实] Patrick 解释 Clink 在 2025 年中决定做 agent 支付并选择法币方向，是因为消费者信任问题在法币体系里更好解决。

[事实] 他认为银行和传统卡支付体系中的消费者保护已经比较成熟，而 Web3 支付一旦付出后目前看较不可逆，会影响消费者信心。

[推测] 法币方案的优势不是技术更轻，而是更容易继承现有支付体系中的争议处理和消费者保护机制。

[13:37] **小额授权与 token 消耗的真实痛点**

[事实] 主持人举例说，有公司在解雇人员后某晚 token 突然烧掉 600 多美元，难以判断是 API 被盗、权限未回收，还是任务异常运行。

[事实] 这个例子引出了按人分配单独 API、可追溯消费来源的重要性。

[事实] Patrick 回忆 Clink 三月发布法币体系下的 agent 充值能力时，高宁作为早期用户非常谨慎，每次只充值 1 美元，而不是建议的 10 美元。

[事实] 嘉宾认为，在长任务中给 agent 小范围授权，可以让它不必停下来等人续费或补充资源。

[16:01] **稳定币与链上支付的机会**

[事实] Patrick 说稳定币方向的玩家很多，包括 Stripe 和 Coinbase。

[事实] 他认为如果只是让 agent 做小额支付，稳定币体系在技术上相对成熟，因为逻辑接近多端到多端转账。

[事实] 他提到链上也有人尝试用智能合约做类似中间担保，把钱暂存在某处，确认交付后再释放给商家，以缓解完全不可逆的问题。

[事实] Visa、Mastercard 也在稳定币方向布局，但更多可能用于 B2B 结算体系，因为稳定币相对传统 Swift 跨境转账有成本和效率优势。

[18:18] **技术能跑通，但体验还不够顺滑**

[事实] 主持人总结说，无论法币还是稳定币，技术层面似乎都比较 ready，关键是需求端什么时候爆发。

[事实] Patrick 回应说法币体系能跑通，但授权认证、追责和 liability 归属受到重视，因此流程体验还不够丝滑。

[事实] 如果用户觉得 agent 支付和自己下单一样繁琐，就可能放弃使用。

[推测] 未来竞争焦点会从“能不能付”转向“能不能在安全可信的前提下减少打断”。

[19:37] **商户面对多协议的接入复杂度**

[事实] 主持人提到 Google、OpenAI 等都有相关协议，商家可能面对多套复杂协议而一头雾水。

[事实] Patrick 说电商本身就复杂，涉及 catalog、商品发现、优惠券、积分、运费、支付方式等，因此协议不可避免复杂。

[事实] Clink 希望降低商家 onboarding 成本，让更多商户能以插件安装或简单接入的方式变成 agent payment ready。

[20:31] **授权频率是当前体验瓶颈之一**

[事实] Patrick 用与 HaloMind 和 Visa 的 demo 举例说，在一次性沟通中，用户每次都需要明确授权。

[事实] 他认为如果用户每次都买 20 元一包纸，能否减少重复授权，是一个尚未有标准答案的问题。

[事实] 对虚拟商户或订阅场景，用户授权 100 元额度、每次充值 10 元这样的流程相对更容易跑通。

[推测] 实物电商里的动态商品、价格和履约差异，使长期授权和自动支付更难标准化。

[22:01] **Clink 试图做多协议、多平台的衔接层**

[事实] Patrick 表示 Clink 不是押注一条特别固定的技术路线，而是希望尽可能兼容更多协议、商家和平台。

[事实] 他提到 Clink 正在兼容 UCP，下一步会看 ACP；平台方面兼容 Shopify，并研发 Magento、WooCommerce 等插件。

[事实] 他把 Clink 比作多条高速公路之间的匝道：当用户从一种协议来、商户使用另一套收单或支付体系时，中间需要转换和衔接。

[推测] 这种定位的价值在于减少商户和 agent 平台之间的碎片化成本，而不是替代所有支付公司。

[24:26] **与 Stripe 的差异：中立性和覆盖面**

[事实] 主持人问到 Clink 相比 Stripe 的优势，以及如果大厂入场怎么办。

[事实] Patrick 认可 Stripe 在 agent payment 和 agent commerce 早期做了很多优秀工作，也说 Clink 在学习他们。

[事实] 他认为 Stripe 的核心定位仍是收单和支付公司，因此其协议可能面临“既是裁判员又是运动员”的疑虑。

[事实] Patrick 认为全球支付市场既 global 又 local，许多普通商户仍使用本地收单机构，因此需要一个更中立的衔接层来帮助处理海外 agent 用户的支付请求。

[27:23] **高宁看赛道：需求会从任务结果出发**

[事实] 高宁说自己曾担心商家侧供给动力不足，因为商家通常希望用户来到自己的平台完成支付和订阅。

[事实] 他认为 agent payment 的推动意味着用户可以直接在 agent 里布置任何任务，而任务长度和复杂度会越来越高。

[事实] 他举例说自己愿意在 Codex 或 ChatGPT 里下达命令，只关心结果，不在乎中间用了什么工具或 skill。

[事实] 当第一次流程给出好结果且价格合理后，用户可能希望以后同类任务直接扣款，不再反复授权。

[29:23] **国内生态：支付基建成熟，但场景还在形成**

[事实] 主持人提到支付宝也官宣了 agent payment，询问国内外生态差异。

[事实] Patrick 认为国内有不同的行业特性，海外卡支付中的 dispute 和盗刷争议在支付宝、微信支付场景里较少见。

[事实] 他认为国内电子支付普及率高、基础设施成熟，关键是找到适合 agent 使用的路径。

[事实] 他提到腾讯 agent 卡、支付宝 AMP 协议等方向，但也表示还没看到最终产品层面和场景层面的落地。

[推测] 国内如果结合微信等高频生态，agent payment 的大规模使用可能会出现得较快。

[31:04] **海外大规模爆发需要普通用户先接受 agent**

[事实] Patrick 认为 agent 支付和 agent commerce 已经是行业共识，但从行业共识到普通用户共识还需要时间。

[事实] 他指出今天 agent 在普通用户中的覆盖率仍然不足，而这些普通用户可能正是电商主力人群。

[事实] 在 agent 普及之前，Clink 希望先做好 merchant readiness，让商户的支付、订单等原生能力变得 agent friendly。

[推测] 海外市场的爆发节奏可能取决于两个前提同时成熟：用户常态化使用 agent，以及商户端已经完成接入准备。

[32:23] **从绑卡到给 agent 一张卡**

[事实] 高宁补充说，第一阶段是各种 skill 背后对应公司的产品，用户给搜索或服务产品绑卡或充值，再按用量消费。

[事实] 第二阶段是用户真正给自己的 agent 一张信用卡，让 agent 为了解决任务进入 marketplace 或互联网搜索并调用合适的 skill。

[事实] 他认为第二阶段仍需要授权，但会更接近“agent 拿着卡去消费并完成任务”的形态。

[推测] 这代表信任边界从单个产品扩展到用户自己的 agent，也是支付基础设施更复杂的下一步。

[34:04] **内容创作者如何在 agent 入口时代变现**

[事实] 主持人从内容创作者角度提出问题：如果用户入口变成 agent 或 AI，内容被自动抓取和呈现，中间内容创作者如何变现。

[事实] Patrick 认同这个观察，并指出注意力经济中内容可以免费，但人类注意力带来广告等变现路径；agent 抓取时可能看不到广告。

[事实] 他提到一种思路是人看内容免费，agent 抓取或爬取内容要付费，但也认为这个逻辑并不特别成立，因为用户可能会寻找免费路径。

[事实] Patrick 提到早期互联网也曾有访问网页付费的设想，但后来商业化走向了其他路径。

[推测] agent 时代的内容商业化可能还处于非常早期，只有创作者能挣到钱，生态才会健康。

[37:09] **未来半年到一年最想看到的市场信号**

[事实] Patrick 希望看到用户在社交平台分享自己用 agent 购物，并获得之前没想到但很喜欢的推荐，产生 aha moment。

[事实] 他还希望看到更多 agent 调用 digital service 或付费外援完成任务，并且结果足够好，形成用户分享。

[事实] 主持人提到自己生病出差期间一直和 ChatGPT 讨论症状、用药和益生菌推荐，但最后仍要去其他平台下单。

[事实] 主持人希望未来 agent 能直接对接医生、开处方或下单购买相关产品，并寄到家里。

[推测] 健康咨询到电商履约的闭环，是主持人认为消费者端已经很接近 ready 的具体场景。

[39:48] **收束：期待 agent economy 带来更便捷生活**

[事实] 主持人总结本期讨论覆盖了从年初 agent 大火到半年内行业在 agent payment 上的推进。

[事实] 主持人感谢两位嘉宾，并表达希望 Clink 作为 agent economy 的一员，更快让用户过上更方便、便捷的生活。

[40:20] **片尾推荐：新加坡雨水友好设计**

[事实] 节目片尾介绍新加坡是爱下雨的热带城市，但许多人上学上班乘公共交通可以不用打伞。

[事实] 片尾提到新加坡组屋一层常设计成架空、四面通风的空间，组屋之间和公共交通枢纽之间有遮雨连廊。

[事实] 片尾还提到新加坡近几年开发带屋顶的公共广场等雨水友好设计，并推荐收听播客《knock knock 世界》。

## 播客点评/总结

这一期的价值在于把 agent payment 从概念拉回到真实支付系统：不是简单给 AI 一张卡，而是要处理用户意图、额度授权、商品校验、一次性支付、责任归属、商户接入和争议处理。Patrick 的支付从业背景让讨论明显偏基础设施视角，能帮助听众理解为什么支付链路比“让 agent 点击付款”复杂得多。

亮点是把法币、稳定币、电商、skill 调用、内容变现和国内外生态放在同一张图里讨论。节目没有停留在大厂新闻罗列，而是用 Clink 与 Visa 的 demo、小额 token 充值、API 消耗失控等例子，解释智能体支付真正卡在哪里。

局限是部分协议名称和产品细节在转录稿中较口语化，节目也没有展开具体技术接口、风控模型或商户改造成本的数据。[推测] 因此它更适合想理解赛道结构、商业机会和关键阻力的创业者、投资人、产品经理和 AI 应用开发者，而不是寻找落地接入教程的工程团队。
