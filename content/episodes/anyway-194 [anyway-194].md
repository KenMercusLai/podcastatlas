# 从 MacRabbit 到 Codex：AI Coding 时代的独立应用与设计师创作

## 概览

本期从节目久未更新、录音条件随意和会员群迁移通知开场，随后进入核心话题：AI Coding Agent 爆发后，设计师和创作者如何重新获得制作独立应用的能力与冲动。

节目上半部分回顾 MacRabbit 及其代表产品 CSS Edit、Espresso、Slicy。两位主播重点讨论这些 Mac 独立软件在功能、审美和工作流上的影响，尤其是 Espresso 让人“想去编程”的视觉品质，以及 Slicy 对设计交付和切图流程的改变。

节目下半部分转向今天的 Codex、Cursor 等 AI Coding 工具。主播认为，AI 让从 0 到可用原型的成本大幅下降，也让设计师可以用草图、Figma、截图和自然语言参与“写代码”。但他们也强调，从 0.9 做到可靠的 1.0 仍然很难，真正发布给大量用户使用会暴露大量体验、兼容性和工程问题。

## 分段落总结

[00:16] **节目回归与开场说明**

[事实] 主播表示距离上一期节目已经过去较久，甚至片头词都找了几分钟才找到。

[事实] 本期从选题到录制都比较随意，一位主播说明自己不在家中录音，只能在公司里凑合录制。

[事实] 开场还提到会员群出现问题，原本在会员群里的听众如果想继续聊天或潜水，可以通过微信联系重新拉入新群。

[推测] 这一段奠定了本期较为闲聊、怀旧和即兴的语气。

[02:16] **AI Coding Agent 爆发与本期主题**

[事实] 主播提到春节后 AI Coding Agent 大爆发，包括 Claude Code、Codex、Cursor 以及大量国内外 AI 编程工具。

[事实] 社交媒体上出现“全员 Vibe Coding”的状态，越来越多非传统程序员也开始用 AI 做产品。

[事实] 一位主播说自己最近深入使用这些工具，目前主要使用 Codex，并感到像回到十年前做设计时的状态。

[推测] 本期标题“从 MacRabbit 到 Codex”把早年 Mac 独立软件文化和今天 AI 辅助创作连接起来。

[06:33] **小而美的 Mac 独立应用记忆**

[事实] 主播回忆，很多同龄或稍年轻的从业者第一次想买 Mac，是因为被 macOS 上小而美、精致的独立应用吸引。

[事实] 他们提到这些应用在当年 Windows 生态里很难感受到，带来很强的新鲜感和审美冲击。

[事实] MacRabbit 被引出为那个年代“又好看又好用”的 Mac 应用创作者之一。

[推测] 主播把 MacRabbit 视为独立软件黄金时代的代表案例。

[07:45] **MacRabbit 与其低调作者**

[事实] 主播介绍 MacRabbit 是一个非常小而独立的工作室，接近今天流行的 One Person Company 概念。

[事实] MacRabbit 背后的作者是比利时人，名字发音较难，且非常低调，缺少采访视频等资料。

[事实] 主播说作者大约在 2003 年前后、高中时期开始写 Mac 软件，第一个软件用途是遮住杂乱桌面。

[事实] 被重点提到的 MacRabbit 产品主要有 CSS Edit、Espresso 和 Slicy。

[09:03] **CSS Edit、Espresso 与 Slicy 的分量**

[事实] 主播认为虽然 MacRabbit 代表作数量不多，但每一个在当时都很有影响力。

[事实] CSS Edit 很早为 MacRabbit 赢得 Apple Design Award，并在一定程度上定义了后续代码工具的形态。

[事实] 主播认为 CSS Edit 也是后来的 Espresso 的基础。

[推测] 这些软件的意义不只在于功能本身，也在于它们展示了一个人或极小团队也能做出高完成度工具。

[11:29] **Espresso：面向 Web 的全功能代码编辑器**

[事实] Espresso 被主播称为 MacRabbit 最重头的产品，是一个全功能代码编辑器，主要面向 Web 开发。

[事实] Espresso 内置 FTP 上传、浏览器预览等功能，并继承了 CSS Edit 的底子。

[事实] 主播长期把 Espresso 作为主力工具使用，并表示至今还装在电脑里。

[事实] 主播提到 Espresso 迭代了十来年，直到 2018 年因作者去 Framer 工作而被卖掉或停止原作者维护。

[14:45] **Espresso 的审美与工具体验**

[事实] 主播认为 Espresso 最核心的特点是漂亮，漂亮到让人想去编程。

[事实] 主播回忆那个年代 macOS 软件常见的精致视觉语言，包括淡阴影、一像素高光、淡渐变和柔和控件。

[事实] Espresso 在写网页代码的范围内功能足够强大，内置浏览器和预览能力在当年已经提供类似所见即所得的体验。

[推测] 主播怀念的不是单纯的拟物风格，而是工具在功能、视觉和情绪上的统一。

[18:26] **Sugar、字体与有温度的设计**

[事实] Espresso 的皮肤不叫 Theme，而叫 Sugar，呼应 Espresso 咖啡加糖的命名趣味。

[事实] 主播认为这种细节会让在乎的人感到作者和使用者之间有共鸣。

[事实] 主播还提到自己喜欢 Espresso 自带的等宽字体，认为它不像 VS Code 等工具那样有强烈“程序员味”。

[事实] 一位主播说自己后来在 Espresso 不能满足需求后，仍长期选择 Atom 而非 VS Code，因为更能接受 Atom 的设计品位。

[20:38] **Slicy 对设计师的冲击**

[事实] 主播认为 Slicy 比 Espresso 在当下可能更“没用”，但更值得从设计师角度聊。

[事实] Slicy 被描述为无需手工准备切片的图片输出软件，通过给图层打标签建立了现代输出范式。

[事实] 主播认为 Slicy 对当时设计师的影响非常大，显著减少了切图工时。

[推测] Slicy 的价值在于它把繁琐体力活变成了一个更系统、更优雅的工作流。

[22:14] **早年切图与设计交付的痛苦**

[事实] 主播解释，当年用 Photoshop 做 UI 设计时，设计师要把设计稿中的 assets 手动分门别类保存给前端开发。

[事实] 除了保存图片，还需要做标注，而不像今天使用 Figma 那样方便。

[事实] 当年很多视觉效果难以直接用程序实现，常常需要导出图片，包括按钮、圆角框、九宫格等资源。

[事实] 主播提到有些公司甚至会配专门负责切图的人。

[26:19] **Slicy 的命名规则与自动导出**

[事实] Slicy 的工作方式是按规则命名 Photoshop 图层，再把 PSD 文件拖入 Slicy，即可自动生成切片。

[事实] 主播认为这套方式和后来 Sketch、Figma 中为对象设置 Export 的核心理念相似。

[事实] Slicy 不需要改动原有工作流或安装复杂插件，只通过命名就能完成输出。

[事实] 主播举例说，可以通过类似 icon.png、icon.png @2x 的命名方式输出不同倍数的资源。

[推测] Slicy 的优雅之处在于它用很轻的介入方式解决了复杂协作问题。

[29:11] **Slicy 的动画、行业采用与后续影响**

[事实] 主播回忆把 PSD 拖进 Slicy 后的转换动画非常有 Mac 软件气质，让切图从痛苦工作变成一种享受。

[事实] 主播提到 Slicy 出现后不久，Photoshop 也加入了类似通过命名规则导出的功能。

[事实] 主播认为 Photoshop 的实现没有 Slicy 好用。

[事实] 节目还提到 Zeplin，但认为 Zeplin 的野心更大，因为它还包含标注能力。

[31:25] **独立开发的难度与对 MacRabbit 的重新敬意**

[事实] 主播说在“默默语2.0”发布后、面对很多投诉时，自己对 MacRabbit 作者的敬意更深。

[事实] 主播认为设计师往往有做出好看、好用、有温度产品的愿望，但把体验做到没有明显问题非常难。

[事实] 独立开发者在人力、测试时间有限的情况下，要做出功能完整且考虑各种意外情况的软件，是很大的工程挑战。

[事实] 主播提到自己做产品时有些心力交瘁。

[推测] 这一段把怀旧转化为现实经验：真正的软件品质来自大量难以被外部看见的工程细节。

[34:39] **Markedown、更新说明与 AI 生成文档**

[事实] 一位主播提到另一位做了 Markedown 这样的 Markdown 编辑器产品，并关注其更新内容。

[事实] 被提到的主播纠正说，发在推特上的更新通知是自己写的，而 README 是让 Codex 自动生成的。

[事实] 主播表示这个产品首先是满足自己的使用需求。

[推测] 这段显示 AI 已经进入他们的产品开发和文档工作流，但对外表达和产品判断仍由人来把控。

[36:15] **从 0 到 0.5 的个人工具时代**

[事实] 主播认为在全员 Vibe Coding 的年代，把一个东西做到 0.5 非常快，而做到真正的 1.0 成本仍然很高。

[事实] 如果产品只给自己用，0.5 可能已经足够，因为作者知道 bug 和问题在哪里，也知道如何绕开。

[事实] 主播认为简单或不太复杂的需求，现在可以自己用 AI 做出来，只需花一些 token 和少量服务器成本。

[事实] 另一位主播表示自己做东西既是为了自己用，也希望有更多喜欢同类东西的人来使用。

[39:20] **同时做多个应用与创作感恢复**

[事实] 主播说自己最近用 Codex 同时做四五个不同应用，做累了就换另一个继续。

[事实] 这个过程让他觉得解压，并重新感受到十年前做设计师时的状态。

[事实] 另一位主播说自己的感受不同，已经过了 AI Coding 带来惊艳感的阶段，更处在一种“回潮”状态。

[推测] 两位主播代表了两种 AI 创作心态：一种强调释放想法，另一种强调重新找回亲手写代码的参与感。

[39:51] **Human in the loop 与重新拿回代码激情**

[事实] 一位主播说自己并不怀疑 AI 能做出东西，也认可近半年 AI Coding 进展很快。

[事实] 他在工具选择上更希望保留 Human in the loop，让人的成分更多一些。

[事实] 他表示 AI 带来创作激情后，自己反而想重新拿回以前写代码的激情，继续写自己的东西。

[推测] 这一段的核心分歧不是是否使用 AI，而是人应该在创作流程中保留多少直接操作和细节控制。

[41:34] **设计师如何用 Codex“写代码”**

[事实] 主播认为，对设计师背景的人来说，Codex 这类工具才更像他理解中的“写代码”。

[事实] 他的项目通常先在脑中形成画面，再用 Figma、纸笔草图等方式画出来。

[事实] 他会通过 MCP、拍照、截图等方式把图像传给 Codex，再用自然语言沟通，让工具理解图像并实现产品。

[推测] 对以图像表达为核心的设计师来说，编程的操作层面正在从逐行写代码转向图像、语言和意图的组合表达。

[43:41] **时装设计师、裁缝与 AI 的分工类比**

[事实] 一位主播用时装设计师和裁缝作比：设计师擅长快速 sketch 风格和细化造型，但可能缺少把材料、结构和工艺落成成品的能力。

[事实] AI 工具补上了这部分能力，使设计师不只是画效果图，而能做出可运行的东西。

[事实] 另一位主播则把自己定位为裁缝，认为 AI 让他能把原本底层的手艺扩展到更复杂、更高级的作品。

[事实] 两人最终都认同，在这个时代大家可以选择更适合自己的工作流来完成成果。

[46:43] **AGI、自由工作流与乐观态度**

[事实] 主播提到通用型 AI 的目标是“什么活都能干”，因此未来工作流可以由人自由选择参与哪个环节。

[事实] 主播也提到另一层含义是每个环节都可能被 AI 取代，但没有展开讨论。

[事实] 一位主播表示自己对当下非常乐观，觉得这是精神上很美好的时代。

[推测] 本期对 AI 的态度总体偏积极，但仍保留了对替代风险和工程现实的意识。

[48:05] **默默语 2.0 广告与收尾**

[事实] 主播在结尾为“默默语2.0”做广告，称其在 5 月 13 日刚刚发布。

[事实] 新版本除了单机计时，还加入网页版，可以查看历史数据，并把时间运作规律发送给他人分析。

[事实] 主播强调它更像陪伴，而不是强制、刺激用户去做事的管家或家长。

[事实] 主播承认产品目前不太完善、有不少 bug，也涉及用户隐私，因此理解用户的顾虑，并感谢过去一年多听众的支持。

## 播客点评/总结

[推测] 本期的价值在于把 Mac 独立软件黄金时代和今天 AI Coding 工具放在同一条创作脉络里看：核心并不是“工具更强了”，而是个人创作者重新获得了把想法变成产品的现实路径。

[推测] 节目的亮点是大量具体软件记忆，尤其是 Espresso 的视觉细节和 Slicy 的切图工作流，让“好用又好看”的独立软件不只是抽象赞美，而是落实到命名、动画、导出规则和设计交付的细节中。

[推测] 局限是讨论主要来自两位主播的个人经验，对 AI Coding 的工程边界、商业可持续性和用户隐私问题只是点到为止，没有展开成系统分析。

[推测] 这期适合对 Mac 独立软件、设计工具史、AI 辅助编程、独立开发和设计师产品化感兴趣的听众，尤其适合经历过 Photoshop 切图、早年 macOS 应用生态或正在尝试用 Codex/Cursor 做个人工具的人。
