# 大厂押注AI办公，飞书和钉钉却先成了配角

## 概览

本期围绕飞书组织调整展开，把飞书、钉钉、豆包、腾讯 WorkBody、阿里千问办公等放在同一条“AI 办公”主线下讨论。嘉宾认为，半年前行业还在争夺 C 端 Chatbot 流量，如今焦点迅速转向 Coding、长程任务和办公 Agent。

讨论的核心判断是：AI C 端流量未必等于商业资产，因为每个用户都带来持续算力成本，而广告、电商、订阅等 C 端变现路径都还没有被充分验证。相比之下，办公、Coding、企业数据和工作流更容易承接付费意愿，也更能给大厂讲出新的 AI 增长故事。

节目也反复争论一个关键分歧：未来的钱到底来自企业采购，还是来自“个人为自己的工作生产力付费”。飞书和钉钉原本是企业协同办公的主角，但在 AI 叙事里，它们更像是数据、文档、流程和组织关系的底座，主角变成了模型、Agent 和新办公入口。

## 分段落总结

[00:05] **飞书拆分引出 AI 办公大战**

[事实] 主持人开场提到飞书“被拆分”的新闻，并把飞书、钉钉以及 BAT 的 AI 办公放在一起讨论。
[事实] 节目提出的问题包括：飞书更需要豆包，还是豆包更需要飞书；豆包的两亿日活到底是资产还是负债。
[事实] 嘉宾包括曾在飞书商业化和产品团队工作的 Eric，以及长期观察互联网行业的明昊、雅兰。

[03:53] **豆包更需要飞书，还是飞书更需要豆包**

[事实] 嘉宾认为豆包的 C 端用户会带来巨大的 token 消耗，节目中提到可能达到“百万亿级 token”使用量和百亿级人民币成本。
[事实] 一位嘉宾判断豆包更需要飞书，因为 AI 产品需要通过 2B 方式找到变现入口。
[事实] 另一位嘉宾补充，飞书也需要豆包的 AI 模型和故事，双方在数据、商业化和模型能力上具有互补性。

[09:18] **飞书调整的内部视角**

[事实] Eric 认为，从商业化角度看，火山引擎和飞书面对的是同一批客户、同一笔预算，两个销售团队分开会产生重复和冲突。
[事实] 他提到所谓“豆包企业版”在销售场景里更像是在飞书企业版中加入豆包机器人，客户买 AI，飞书成为承载形态。
[事实] 他还表示，产品侧不一定是飞书产品团队简单并入豆包，而是豆包企业版相关团队回到飞书产品负责人线下；研发汇报线变化不大。

[15:03] **行业重心从 Chatbot 转向 Coding 和办公 Agent**

[事实] 明昊认为，头部厂商在 Coding、长程任务和办公 Agent 上的收入示范效应，推动大厂迅速转向 AI 办公。
[事实] 节目提到春节前后 Open Cloud/“小龙虾”爆火，使各家公司在很短时间内立项、迭代并推出 Work Agent 类产品。
[事实] 嘉宾指出，AI 行业形成共识和抛弃旧共识的速度非常快，周期已经从半年压缩到按月计算。

[18:08] **小龙虾强化了管理层共识**

[事实] 节目提到阿里钉钉紧急整合，飞书也调整汇报关系，腾讯则发布 WorkBody 并提出做“AI 时代的 Office”。
[事实] 嘉宾认为，小龙虾这一波不仅影响了大众用户，也让大厂管理层更清楚 Agent 大致应该长什么样、具备哪些功能。
[推测] 这一轮变化更像是战略认知被统一后的集中投入，而不是单个产品自然演进出的结果。

[21:20] **字节为什么显得慢了**

[事实] 明昊提到，字节内部在相关方向上有飞书智能伙伴、扣子、Trae 等多条线，各自带有原有业务和路径依赖。
[事实] 他回忆 6 月中旬行业大会上，各家厂商在 AI 办公方向的状态并没有明显差距，但 7 月前后 WorkBody 被迅速推到更高位置。
[推测] 多团队并行、成熟业务惯性和协调成本，可能让字节在这轮 AI 办公窗口里没有表现出过去那种“快且锋利”。

[25:15] **个人生产力和企业办公边界变模糊**

[事实] 主持人举例称，个人用户为大模型付的钱可能已经超过协同办公软件费用，老师也会用 WorkBuddy 做备课。
[事实] 节目提到豆包曾尝试商品卡、跳转抖音商城等 C 端商业化方式，但这些尝试没有成为清晰的主路径。
[推测] AI 办公的付费者不一定是公司采购部门，也可能是为工作效率付费的个人员工。

[28:12] **WorkBody 的机会来自非程序员人群**

[事实] 嘉宾认为，AI Coding 方向早已有 Cursor、Cloud Code 等产品，国内能使用这些工具的程序员群体已经被较早教育。
[事实] WorkBody 的机会在于非 Code 人群，他们需要用自然语言处理办公、资料整理、任务执行等场景。
[事实] 节目中提到一个相对可信的数据来源称，WorkBody 已支持百万级日活。

[33:11] **飞书为何没有先长出通用办公 Agent**

[事实] Eric 认为，腾讯没有飞书这样的企业协同办公资产，所以只能做偏个人、本地数据抓取的 WorkBody。
[事实] 他强调飞书内部拥有文档、会议、组织架构、权限等企业数据，飞书智能问答能在权限范围内检索企业文档并生成答案。
[推测] 如果企业已经高度数字化，飞书这类协同工具中的结构化数据会成为 AI 办公的重要壁垒。

[36:47] **C 端路线和 B 端路线的争论**

[事实] 主持人反驳说，中国大量用户并不以组织身份使用 AI，而是以个人身份学习和完成工作。
[事实] 雅兰提到，企业微信之所以强，是因为它连接了大量使用微信的 C 端用户，许多企业场景本质上仍依赖人与人的连接。
[推测] 未来 AI 办公竞争的分歧，取决于增量价值更多来自个人工作入口，还是来自企业内部数据和流程。

[46:01] **飞书和钉钉成为 AI 故事的配角**

[事实] 主持人认为，飞书和钉钉过去几年在 2B 协同办公上竞争，但都没有独立跑成足够支撑集团增长的大故事。
[事实] 节目提到，钉钉上层叠加千问、螺丝快跑、Code Work 等新 AI 办公叙事，飞书则进入豆包和火山引擎相关体系。
[推测] 在 AI 时代，传统企业 IM 的主角位置正在下降，文档、流程、会议和组织数据更像是 Agent 的底座。

[55:00] **模型加业务数据才有真实价值**

[事实] Eric 认为，单有模型还不够，企业的组织架构、文档、会议纪要、审批流、群聊等数据才是 AI 的上下文来源。
[事实] 嘉宾也承认，不同行业和公司使用同一套工具的价值差异可能非常大，传统行业未必像互联网公司一样数据原生。
[推测] AI 办公能否落地，很大程度取决于企业是否已经把关键知识和流程沉淀为可调用的数据。

[63:33] **飞书早期 AI 改版与成熟产品的限制**

[事实] 主持人回忆飞书在 2023 年做过 AI 改版和智能伙伴，后来因为变化过大、客户接受度有限，方向变得更保守。
[事实] Eric 表示飞书后续主要聚焦 AI 和多维表格，并提到飞书已有 Ali 功能，可接入豆包、DeepSeek、Kimi 等不同模型。
[推测] 成熟协同办公产品要服务既有客户和稳定交付，因此更难像新产品那样彻底重构为 AI 原生形态。

[70:20] **豆包 C 端变现三条路受阻**

[事实] 雅兰总结豆包 C 端商业化尝试包括商品推荐/GMV、广告推荐以及 C 端订阅付费。
[事实] 她认为商品跳转带来的单量相对字节广告体量很小，广告会损害用户对答案真实性的信任，C 端付费率也很低。
[推测] 如果只看直接收入，豆包的高日活在 AI 成本结构下可能更像负债；它必须找到 B 端或其他间接变现方式。

[74:39] **豆包的隐性资产是用户画像**

[事实] Eric 提到，AI 的 Memory 能记录用户偏好，而豆包与抖音、巨量引擎账号互通，可能让字节更了解用户。
[事实] 他认为更准确的用户画像可以提升广告推荐、ROI 和广告库存价值。
[推测] 豆包的商业价值可能不只在订阅费，而在于反哺字节广告系统；但这也会带来隐私和信任问题。

[83:59] **品牌形象和组织惯性成为新问题**

[事实] 主持人提到豆包在短视频语境里已有“傻白甜”式调侃形象，和飞书严谨办公品牌并不一致。
[事实] 节目还讨论了 Trae、WorkBody、Code Work 等命名，以及字节多团队协同、中台惯性、A/B Test 文化在 AI 探索中的局限。
[推测] 在没人知道正确答案的 AI 产品阶段，过度依赖数据驱动和组织协同，可能不如小团队凭信念快速打磨产品有效。

[89:00] **AI 办公销售依赖焦虑和生产力叙事**

[事实] Eric 说飞书商业化团队在企业里推飞书时，AI 是最好用的名头，老板和一线员工都会感兴趣。
[事实] 他认为中层管理者焦虑最大，因为当企业信息被数据化后，上传下达这类工作更容易被 AI 替代。
[推测] AI 办公的销售动力不仅来自效率提升，也来自组织内对岗位替代和能力落后的焦虑。

[90:53] **通用办公 Agent 背后仍是 Coding 能力**

[事实] 主持人提出，做网站、处理表格、修改文件和业务流程的通用办公 Agent，本质上可能是把 Coding 能力藏在界面后面。
[事实] 明昊认为，短期共识是 Coding 已成为 Agent、评估、任务分配和自主进化的核心基础能力。
[事实] 他还提到 Codex 类产品定义了当前 Work Agent 常见的三栏形态：项目、对话执行区和运行结果区。

[95:33] **结尾：三家大厂仍没有确定赢家**

[事实] 节目最后盘点腾讯从 WorkBody/CodeBody 接入文档和企业生态，阿里整合千问、螺丝快跑、Code Work 和新钉钉，字节则调整飞书与豆包关系。
[事实] 主持人还提到 360 的 Nami Work 和 WPS Work 也加入竞争。
[事实] 嘉宾没有给出明确赢家，表示要等豆包企业版、千问办公等产品继续跑出数据后再判断。

## 播客点评/总结

[事实] 本期价值在于把飞书拆分新闻放进更大的 AI 办公竞争框架中，而不是只讨论单家公司组织调整。嘉宾从商业化、产品形态、企业数据、个人付费和组织机制多个角度解释了为什么飞书、钉钉会从主角变成底座。

[事实] 节目的亮点是内部视角和行业观察交叉：Eric 提供了飞书商业化、产品和企业数据价值的解释，明昊强调 AI 共识变化的速度，雅兰则补充了豆包 C 端商业化受阻的观察。

[推测] 节目的局限是大量判断依赖行业体感、公开报道和嘉宾个人经验，部分产品名称、数据和结论还处在快速变化期，不能视为最终定论。

[推测] 这期更适合关注 AI 办公、企业服务、大厂组织调整和 AI 商业化的人听；如果只想了解单一产品功能更新，节目会显得讨论范围较宽、观点密度较高。
