# Grokbot

## Overview
Grokbot is represented as [[Grok]]'s personalized-bot surface, progressing from accessible custom bots toward persistent cloud execution and visible role-based teams for research, email, shopping, and other tasks.

## Current Profile
The first source places Grokbot in the personalized-AI and user-created-bot branch, emphasizing accessibility rather than benchmark leadership. The second adds cloud continuity: agents can continue after the user's computer is off and could share a room with people and other agents.

The newest episode makes that multi-agent interface concrete. Specialist bots and cloud computers help users see distinct capabilities, while progress updates are compressed into natural language suited to a phone. The source also questions whether users should manage that structure directly. Multiple visible bots can increase coordination, latency, and token use, so a mature product may present one general manager agent that routes work to specialist agents and models behind the scenes.

## Key Characteristics
- Serves as a user-facing personalized-bot product in the [[XAI|xAI]] ecosystem.
- Makes custom agents approachable through named or role-based bot surfaces.
- Supports persistent cloud work beyond a live local session.
- Uses multiple specialist bots and cloud computers to make execution capabilities visible.
- Raises unresolved questions about memory, permissions, coordination, cost, and whether internal agent teams should be exposed to users.

- Persistent execution and shared rooms: [[all-in-with-chamath-jason-sacks-friedberg-nvidias-historic-quarter-saas-comeback-bessent-vs-druck-americas-debt-crisis-cancer-vaccine-42597345]] describes work continuing after a local computer is off and imagines multi-agent, multi-human rooms.
- Specialist-bot interface: [[275-ai-bangong-de-renao-hai-mei-san-geren-agent-de-zhanzheng-yijing-kaishi-chaijie-town-instinct-grok-bot-yu-muse-lpos2jcsbaob2mpwqauzv5xq4_hd]] describes research, email, health, and shopping bots while arguing that one front agent may eventually hide the team and model-routing complexity.

## Qualifications
The sources capture host and guest impressions, not technical benchmarks or safety audits. They do not establish reliability, permission design, cost control, recovery behavior, or comparative performance. The claim that one general manager interface will replace visible bot teams is a product forecast, not an observed endpoint.

## What Changed
- Added role-based specialist bots and mobile-friendly progress reporting.
- Added the cost and coordination case for hiding multi-agent structure behind one front agent.
- Connected product education value to a possible longer-term simplification of the interface.
