# Model-Product Progress Gap

## Definition
The model-product progress gap is the distance between an AI model demonstrating a capability and a dependable product turning that capability into a coherent workflow, user journey, interaction system, and professional outcome.

## Current Synthesis
Model releases can make a product category look suddenly solved because capability demos are visible and easy to compare. Professional software still has to absorb those capabilities into detailed interactions, audience-specific workflows, reliability expectations, and user control. The gap therefore creates room for focused application companies, although it is not a permanent moat if their workflow advantage stops evolving.

## Key Claims
- A model capability demonstration is not equivalent to an end-to-end product.
- Professional products accumulate value in workflows, interaction details, user journeys, and audience understanding.
- Specialized application companies can compete with frontier labs when they make strong product choices for a defined user group.
- Model announcements can trigger exaggerated “company is over” narratives before product substitution is demonstrated.
- The gap is contingent: generic features remain vulnerable as model providers move into application workflows.

## Counterevidence & Qualifications
The source does not establish how large or durable the gap is, and its Figma conclusion comes from Figma's own chief executive. Some application functions can be absorbed rapidly by model providers, particularly when they are generic, lightly integrated, or easy to reproduce. Product depth is a competitive hypothesis that must be supported by retention, willingness to pay, and outcomes.

## What Changed
- Established a canonical distinction between capability progress and product progress.
- Added professional-tool interaction depth and audience focus as application-layer evidence.
- Kept the moat conditional rather than treating specialization as permanent protection.
