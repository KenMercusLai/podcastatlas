# Enterprise Agent Memory

Enterprise agent memory is the company-centered memory layer required when agents work for an organization rather than only for one user. In [[women-shi-ruhe-dingyi-openclaw-for-teams-xin-chanpin-xingtai-de-duitan-kuse-junior-lianchuang-jian-cto-yuhao-lkp1a0todflxoyycyo3zhrap3ebv]], [[Yuhao]] uses [[Junior]] to argue that a team agent should first work for the company and only then for an individual manager.

This extends [[PersistentAgentMemory]] by changing the unit of memory. The agent needs project history, company priorities, customer context, role relationships, private-versus-shareable information, prior decisions, and operating norms. It also needs forgetting, permission filtering, and auditability because richer memory can become a liability if a coworker asks for salary data, customer secrets, or another person's private remarks.

## Key Claims
- Enterprise memory should be organized around company, project, and organizational relationships rather than one owner's preferences.
- The agent must know what not to reveal, not only what to recall.
- Memory quality depends on [[EnterpriseAgentGovernance]] because access, retention, retrieval, and sharing rules are part of the same system.
- Enterprise memory can become a product moat only if it is trusted enough for customers to connect real company data and workflows.
