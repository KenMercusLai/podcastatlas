# Robot Demo Authenticity

Robot demo authenticity is the trust boundary [[YaoSong]] draws in [[173-duihua-yao-song-shenjian-dongfang-kongjian-zaichufa-tiancai-shaonian-shinian-hou-1-173-1]] for evaluating robotics and physical-AI companies. He says some industry demos use teleoperation video as if it were autonomous capability, and that [[StridingAI]] should mark video speed倍率 and whether a demo is fully autonomous.

The concept extends [[TechnicalDemoRetentionGap]] into [[EmbodiedAI]]. A software demo can mislead about retention, but a robot demo can mislead about autonomy, latency, safety, dexterity, reliability, or operator involvement. Because physical robots are expensive and safety-sensitive, unclear demo provenance can distort financing, hiring, customer expectation, and data collection.

## Key Claims
- Speed changes should be labeled because a sped-up robot video can hide latency or operational slowness.
- Autonomy status should be labeled because teleoperation, remote takeover, scripted playback, and full autonomy imply different model capability.
- Demo authenticity is not only ethics; it protects product planning and investor judgment from false milestones.
- The concept connects to [[RobotActiveUseMetrics]] because repeated real use is a stronger signal than one polished video.
