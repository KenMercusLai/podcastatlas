# Agile Sprint Personal Workflow

## Definition
Agile sprint personal workflow is the use of short planning, execution, review, and retrospective cycles to turn personal projects into inspectable increments rather than long waterfall commitments.

## Current Synthesis
The episode introduces agile development by contrasting waterfall software projects with one- or two-week sprints that produce usable increments and feedback. The personal translation is a weekly sprint: plan a bounded set of work, execute, review what was actually delivered, and adjust the system instead of simply blaming effort.

The host maps Scrum roles onto one person. Product-owner judgment selects value, execution advances tasks, and [[FlowMasterPersonalWorkflow]] observes the process, diagnoses friction, and revises the workflow.

## Key Claims
- Short sprints reduce the risk of long-cycle work that receives feedback too late.
- Personal projects benefit from reviewable increments rather than vague ongoing effort.
- Weekly retrospectives make workflow failure visible and improvable.
- A single person can separate value selection, execution, and process-improvement roles.
- Agile personal workflow complements WIP limits because each sprint bounds active commitments.

## Counterevidence & Qualifications
Agile terms can become ceremony without meaningful feedback. The episode's personal version is valuable only when the sprint changes work selection, WIP, review quality, or process design.
