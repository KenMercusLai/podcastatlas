# Open Source Wedge

Open source wedge is the startup pattern where a small open-source component reveals a larger paid product opportunity. [[peter-tsr-v3-audio-converted-peter-tsr-v3-audio-converted]] adds the concept through [[AnalyticsJS|analytics.js]]: the [[Segment]] team had built larger planned products, but the open-source routing library attracted stronger demand when it was posted to [[HackerNews]].

The wedge is not the same as [[OpenSourceCommunityCommercialization]]. Segment did not first build a broad community project and then monetize governance or hosted reliability. Instead, a small internal utility exposed a painful integration job: users wanted the library plus a hosted control plane where destinations could be changed without repeated engineering work.

## Key Claims
- A small open-source artifact can reveal demand that planned product discovery missed.
- Public developer response is useful only when it points toward a recurring operational problem, not just stars or applause.
- The paid product often emerges around hosting, workflow control, reliability, or integration management rather than around the open-source code itself.
- An open-source wedge can combine [[InternalToolProductization]] with [[CustomerEvidenceStrategy]] when the original internal use case recurs across many companies.
