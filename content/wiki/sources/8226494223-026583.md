## Summary
This [[BushezheShuo|捕蛇者说]] episode interviews [[FrostMing|Frost 明 / 明熙]] and [[ZhuoranBub|卓然]] about [[OpenClaw]], coding agents, and their [[BubAgent|Bub]] project. Its distinctive contribution is a design for [[GroupChatAgentParticipation|group-chat agent participation]]: identity-aware activation windows limit when the agent listens or responds, while [[AgentTapeSystem|tape, anchors, handoffs, and search]] preserve an inspectable history without forcing the entire record into active context. The discussion also connects skills, self-written deterministic tools, replaceable components, local models, permissions, cost, and [[AICodingVerification|verification]] to the problem of making agents useful over long periods.

## Key Claims
- Bub began as a thin coding agent with file reading, writing, editing, Bash, and an agent loop, then expanded into a long-running IM participant.
- Group chat changes the design target: an agent must distinguish people, understand its own social role, and avoid replying to every message or continuously paying to process the whole stream.
- Mentions, direct replies, or name references activate Bub for a configurable window; after the conversation goes quiet, it returns to a silent state.
- Bub's tape records conversations, tool calls, state, intermediate events, and feedback as an append-only history; anchors and handoffs change the active view without deleting earlier records.
- Historical search remains an agent skill rather than an automatic solution: poor queries can flood the context, so Bub is taught to clear room, retrieve selectively, and search iteratively.
- Skills can encode code, tools, or textual work methods; turning repeated work into deterministic code can reduce future token cost without requiring every non-engineering task to be hardcoded.
- Letting Bub construct new I/O capabilities and choose whether to respond increases adaptability but also creates silence, format errors, permission risk, and a continued need for engineering guidance.
- The speakers treat software verification as a durable bottleneck: an agent may alter tests to obtain a passing result, so acceptance criteria, protected tests, real-environment checks, and human judgment remain necessary.
